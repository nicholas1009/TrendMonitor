## 原DATA_INCOMPLETE根因

`longbridge==4.5.0` 在本机返回没有 `tzinfo` 的 datetime，其数值代表本机本地时间。本机为 Asia/Tokyo，例如 SDK 的 `2026-08-28 16:00:00` 实际对应 `07:00 UTC / 15:00 Asia/Shanghai`。

旧 Provider 将 naive datetime 直接 `replace(tzinfo=UTC)`，造成时间整体后移9小时；合法A股 Bar 随后被交易时段 Validator 拒绝。MarketDataService 再把单源失败汇总成 `DATA_INCOMPLETE`，因此掩盖了根因。

修复后使用 `datetime.timestamp()` 按 SDK 的本地时间语义生成 epoch。失败汇总仍保留顶层 `DATA_INCOMPLETE` 兼容性，同时新增 provider、原类别、原消息、失败阶段、Raw路径和 provider code（存在时）。

## 长窗口OHLC质量发现

对四个标的分别请求最近1000根15m/60m后，发现少量09:30 Bar的 `open` 位于源端 `high/low` 范围之外：

| Symbol | 15m异常/1000 | 60m异常/1000 |
| --- | ---: | ---: |
| 600487.SH | 0 | 0 |
| 002463.SZ | 0 | 1 |
| 000905.SH | 3 | 11 |
| 000688.SH | 5 | 15 |

本次观察到的异常均发生在09:30。例：`000905.SH` 2026-08-05 09:30 60m 为 open 7567.96、high 7718.39、low 7569.98、close 7705.65；同日日线 low 为7567.96。由数值推断，源端分钟 `open` 可能包含开盘价，而分钟 high/low 的统计范围可能不包含该开盘成交，但当前没有显式字段证明这一语义。

因此未放宽 Validator，也未改写 Raw。最近120根中证500 60m包含上述异常，业务链明确返回 `INVALID_DATA`，Raw Cache状态标记为 `INVALID`。这属于源数据口径风险，不是分钟接口不支持。

完整机器可读5日报告保存在本地 `data/reports/longbridge_minute_structure.json`；真实分钟 Raw 位于 `data/raw/longbridge/15m|60m/`，抽样 Raw/Normalized 位于 `data/samples/longbridge/` 和 `data/samples/normalized/`。
