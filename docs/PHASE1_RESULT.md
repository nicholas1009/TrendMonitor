## Q4｜15m / 60m 能否直接获取？

不能。

- 官方契约：股票、指数/板块、ETF 公开历史行情只支持 `1d`。
- 实际调用：股票历史分别传 `interval=15m` 和 `interval=60m`，均返回 `code=1002`。
- 结论：15m `UNSUPPORTED`；60m `UNSUPPORTED`。不能标记为 `DIRECT`。

## Q5｜若不能，实时采样构造 K 线是否可行？

技术上可行，分类为 `LOCAL_AGGREGATION`，但只能生成明确标记的本地采样 bar。

快照已真实返回价格、源时间戳、累计成交量和累计成交额，因此可以保存采样点并按边界聚合。限制是有限频率可能漏掉真实区间高低点；停机路径不能回补。午休必须切段，交易日使用官方日历，任何缺口必须返回 `DATA_INCOMPLETE`。本 Task 未建立采集 Daemon。

## Q6｜是否仍需 Longbridge 作为另一数据源？

仍建议保留。

主要用途是：交叉验证日线/快照；评估是否能直接提供分钟 K；在同花顺限流、服务异常或标的映射缺失时故障降级。本 Task 不接入 Longbridge。

## Q7｜进入 Phase 2 前最大的技术风险是什么？

最大的风险是短时成功不能代表长期无人值守稳定性，尤其是盘中采样频率、动态限流、网络中断、重启缺口和累计量额语义。第二风险是不同 Provider 的标的体系不一致，例如外部 `BK0437` 不能无损映射到同花顺目录。
